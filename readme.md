# Student Dropout Risk Prediction

An applied machine-learning study of how well routine engagement data can identify students at risk of dropping out, built as a reproducible Python pipeline with leakage controls, a baseline-versus-comparison model design, and error analysis.

> **Status:** code and tests are complete. Results below must be generated by running the pipeline on the dataset (see *Reproduce the experiment*); no numbers are reported here that the code did not produce.

## Research question
How effectively can machine learning identify students who drop out, using attendance, quiz, assignment-completion and engagement data?

## Objectives
1. Audit the data (types, missing values, duplicates, class balance, leakage risk).
2. Explore relationships between engagement measures and dropout.
3. Compare a baseline (Logistic Regression) with one additional model (Random Forest), plus a majority-class floor.
4. Evaluate with precision, recall, F1, PR-AUC and confusion matrices, not accuracy alone.
5. Document findings and limitations honestly.

## Dataset
Table `student_engagement` with columns `student_id`, `attendance_rate`, `avg_quiz_score`, `assignment_completion`, `engagement_score`, `risk_level`, `dropped_out` (target).
The CSV is not committed. Place it at `data/student_engagement.csv`. **Source / licence: _fill in before publishing._**

## Data preparation
- Identifier `student_id` is dropped.
- `risk_level` is **excluded by default**: it looks like a derived score (low/medium/high) rather than a raw measurement, so it may encode the outcome or the other features. `python -m src.eda` tests this (how well the other features reproduce it, and how it relates to dropout). Re-include it with `--include-leakage-suspects` to measure its effect.
- Exact duplicate rows and rows with a missing target are removed.
- Median imputation and standardisation (numeric) and one-hot encoding (categorical) run **inside a scikit-learn Pipeline**, so they are fitted on training data only.
- Stratified 80/20 split, `random_state=42`.

## Exploratory analysis
`python -m src.eda` writes to `reports/`: target distribution, feature distributions by outcome, correlation heatmap, single-feature AUC table (values near 1.0 flag leakage), and `eda_summary.json`.
In the earlier notebook output (`images/1.png`), the engagement-score boxplots for dropped-out and retained students look almost identical, which suggests weak separability from that feature alone. Confirm with the regenerated figures.

## Methodology
| Model | Role | Notes |
|---|---|---|
| Majority-class | Floor | Shows what accuracy is "free" given class imbalance |
| Logistic Regression | Baseline | `class_weight="balanced"` |
| Random Forest | Additional model | `class_weight="balanced_subsample"`, 300 trees, `min_samples_leaf=5` |

Model selection uses 5-fold stratified cross-validation F1 **on the training set only**. The test set is used once for final reporting. Default decision threshold is 0.5; PR-AUC and ROC-AUC are threshold-independent.

## Evaluation
Accuracy, precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix and classification report per model; mean feature values for TP/FP/FN/TN groups (`error_analysis.csv`); permutation importance for the selected model.
- **False negative** = an at-risk student the model misses (no support offered). Usually the costlier error here.
- **False positive** = a student flagged who would have stayed (wasted outreach).
- **Class imbalance** means accuracy is misleading: a model that predicts "stayed" for everyone scores well on accuracy.

## Results
_Run the pipeline, then paste `reports/results.md` here._

Context from the earlier version of this project (`images/3.png`, a single model, ~8,000 test rows): 6,824 TN, 9 FP, 1,163 FN, 4 TP. That is about 85% accuracy but recall of roughly 0.3%, i.e. the model predicted almost no dropouts. The accuracy figure was driven by the majority class. The rebuilt pipeline addresses this with class weighting, a majority-class floor, and recall/F1/PR-AUC reporting.
